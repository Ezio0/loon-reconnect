## 2026-11-19 的连接确认与恢复验证

先添加系统恢复测试，原实现因缺少恢复调用和失败结果而未通过。
实现后，全量 30 项测试通过。新增场景包括：

- 两次 URL 成功派发却均未生效、更新后断开、所有 URL 失败时的系统恢复。
- 已连接时不发送系统启动；首次系统启动失败后第二次恢复，并保留原错误。
- 系统命令成功却始终未连接时，最多尝试两次并明确报错。
- 正在连接或断开时等待有限时间，不反复启动或停止正在过渡的 VPN。
- 按 bundle ID 与 UUID 匹配，支持重命名；缺失、重复、禁用、UUID 异常和外来服务均拒绝。
- 开始前无法读取状态时不关闭 VPN；执行后读取失败仍完成隐藏步骤。
- 不输出系统状态中的扩展详情。

在系统环境单独运行了运行脚本中的服务识别与状态读取函数，
正确识别一个启用的 Loon VPN 服务，返回 `Connected`。
该实机检查不发送 URL，也不调用系统启动或停止。
真实恢复操作和允许激活的 URL 调用仍待实际定时运行观察。

## 历史 Issue #1 的两次开启验证（2026-11-03）

先添加两项测试，在原实现上均失败：缺少第二次 `on`，也没有相应的调用记录。
加入有限重发后，全量 22 项测试通过。新增覆盖：

- 模拟首次 `on` 返回 0 但没有产生连接效果；仍在 10 秒延时后发出第二次 `on`。
- 第一次失败、第二次失败及两次都失败时，仍完成剩余更新与隐藏动作。
- 两次调用各自包含尝试序号；任何失败保持最终非零退出码。
- 完整调用轨迹仅含一次关闭、两次开启、一次更新和一次隐藏；固定等待共 25 秒。
- 各个 URL 失败和全部失败时仍遵守次数限制与执行顺序。

测试中的连接效果是替身状态，用于模拟调用成功但没有效果的情形，
不是对真实 Loon、网络或故障根因的验证。详见 [影响记录](impact/retry-on-dispatch.md)。

## 历史本机窗口隐藏验证（2026-10-30）

在 Loon 3.5.2 上单独验证了实际隐藏子程序：短暂显示现有窗口，再调用隐藏逻辑。
系统状态从未隐藏变为已隐藏，应用进程 ID 保持不变，未退出 Loon。
这项验证没有发送开关 VPN 或更新订阅的 URL，也未修改已安装的定时任务。

第一次尝试发现：即时请求返回值可能让脚本误报失败，而后续独立读取已经是隐藏状态。
修复采用推进运行循环后读取的隐藏状态确认结果；修正后的本机验证通过。
