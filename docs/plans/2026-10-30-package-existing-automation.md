# 现有 Loon 自动化的分发整理

## 授权与范围

用户要求将已经确认并安装使用的功能整理为可上传 GitHub、供其他 Mac 安装的工具。
本次沿用既有 Shell + 用户级 LaunchAgent 方案，属于既有脚本和配置的分发整理；
按工作区配置维护例外实施，不另建产品交付工作流。

保持原重连脚本的行为：关闭 VPN、等待 3 秒、开启 VPN、等待 10 秒、更新全部订阅。
保持默认 6 小时间隔、不在加载时运行、不检测 VPN 状态或网络连通性。
将原说明中的安装、查看任务、手动运行、暂停、恢复、保留备份卸载封装为命令。
安装根据当前用户生成 plist，不携带机器路径；任务标识沿用既有标识以避免重复任务。

## 交付边界

提供独立源码目录、中文 README、MIT 许可证、维护说明、隔离测试与 macOS CI。
用户已授权上传 GitHub；交付范围包括创建公开仓库、首次提交与推送源码。
发布 Release 不在本轮范围内。
不替换本机现有安装，不触发 VPN 开关，不读取 Loon 的订阅或凭证。

## 验收标准

1. 新用户可从下载的源码目录安装，无需 sudo、Homebrew 或 Python 运行时。
2. 用户目录含空格、中文、XML 特殊字符时，生成的 plist 仍可正确读取。
3. 默认间隔为 21600 秒，支持安装时指定整小时数；不设置 RunAtLoad 或 KeepAlive。
4. 重复安装相同版本不覆盖文件；不同内容先提示备份卸载，不静默覆盖。
5. 管理命令发现当前轮次仍在运行时，不卸载或终止该轮；手动运行不使用 -k。
6. 暂停使用 disable + bootout，恢复使用 enable + bootstrap；卸载保留文件与日志。
7. open 失败仍继续后续动作，脚本最终非零退出；sent 不代表 VPN 或订阅成功。

## 验证

Shell 语法检查、Python 标准库完整测试、真实 plutil 解析生成结果、源码隐私和仓库卫生检查。
测试目录位于项目内，launchctl 使用测试替身；运行时测试仅替换 open 和 sleep 的调用路径。
不使用实际代理连接作为测试条件。执行结果记录在 docs/verification.md。
